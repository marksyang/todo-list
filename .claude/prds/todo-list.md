# PRD：Todo List 應用程式

**版本**: 1.0
**狀態**: 草稿
**日期**: 2026-05-19

---

## 1. 背景與目標

### 1.1 背景

使用者日常需要管理多項待辦事項，現有方案（便條紙、備忘錄）缺乏優先順序管理與跨裝置同步能力，導致任務遺漏、效率低落。

### 1.2 目標

- 提供直觀的待辦事項管理工具
- 支援任務分類、優先順序與截止日期
- 降低任務遺漏率 50% 以上（以使用者回報為準）

### 1.3 非目標

- 不做團隊協作功能（v1）
- 不做日曆整合（v1）
- 不做 AI 自動排程

---

## 2. 使用者與使用情境

### 2.1 目標使用者

| 族群 | 描述 |
|------|------|
| 個人生產力用戶 | 每日需管理 5–30 項任務的工作者 |
| 學生 | 追蹤作業、考試準備 |
| 自由工作者 | 管理多個客戶的零散任務 |

### 2.2 核心使用情境

1. **早晨規劃**：開啟 App，快速新增當天任務並設定優先順序
2. **執行中確認**：完成任務後勾選，視覺化當日進度
3. **晚間回顧**：查看未完成任務，移至明日或重新評估

## 3. 功能需求

### 3.1 核心功能（MVP）

#### F-01 任務管理

| 功能 | 描述 | 優先級 |
|------|------|--------|
| 新增任務 | 輸入任務標題，按 Enter 或點擊新增 | P0 |
| 完成任務 | 勾選 checkbox，任務加上刪除線 | P0 |
| 刪除任務 | 點擊刪除按鈕移除任務 | P0 |
| 編輯任務 | 雙擊任務標題進入編輯模式 | P1 |

#### F-02 分類與篩選

| 功能 | 描述 | 優先級 |
|------|------|--------|
| 任務清單 | 依狀態篩選：全部 / 待完成 / 已完成 | P0 |
| 標籤（Tag） | 自訂標籤並以顏色區分 | P1 |
| 搜尋 | 依關鍵字即時篩選任務 | P1 |

#### F-03 優先順序與截止日期

| 功能 | 描述 | 優先級 |
|------|------|--------|
| 優先級設定 | 高 / 中 / 低三級，顯示不同顏色標記 | P1 |
| 截止日期 | 設定日期，到期日前一天發出提醒 | P1 |
| 逾期標示 | 超過截止日期自動標記紅色 | P1 |

#### F-04 資料持久化

| 功能 | 描述 | 優先級 |
|------|------|--------|
| 本地儲存 | 使用 LocalStorage 保存資料（Web） | P0 |
| 帳號同步 | 登入後跨裝置同步（v1.1） | P2 |

---

## 4. 非功能需求

| 類別 | 需求 |
|------|------|
| 效能 | 首頁載入時間 < 1.5 秒（3G 網路） |
| 可用性 | 核心操作（新增/完成）步驟 ≤ 2 步 |
| 相容性 | 支援 Chrome、Safari、Firefox 最新兩個版本；iOS 16+、Android 12+ |
| 無障礙 | 符合 WCAG 2.1 AA 標準 |
| 資料安全 | 本地資料加密儲存（v1.1 後端版） |

---

## 5. UX 設計原則

1. **最少步驟**：新增一筆任務不超過 2 個動作（點擊輸入框 → 輸入 → Enter）
2. **即時回饋**：操作後 100ms 內 UI 更新
3. **可撤銷操作**：刪除任務後 5 秒內可 Undo
4. **空狀態引導**：清單為空時顯示引導文案與新增入口

## 7. 成功指標（KPI）

| 指標 | 目標值 | 衡量方式 |
|------|--------|----------|
| 任務完成率 | ≥ 60%（已建立任務的完成比例） | 後端事件追蹤 |
| 7 日留存率 | ≥ 40% | Analytics |
| 每日活躍任務數 | 平均每用戶 ≥ 3 筆 | Analytics |
| NPS 分數 | ≥ 30 | 月度問卷 |

## 9. 風險與假設

| 風險 | 影響 | 緩解方案 |
|------|------|----------|
| LocalStorage 限額（5MB） | 大量任務可能溢出 | 限制任務數量上限或壓縮儲存格式 |
| 使用者習慣改變成本高 | 低留存率 | Onboarding 流程 + 推播提醒 |
| 競品功能趨同 | 差異化不足 | 聚焦極簡 UX，降低操作門檻 |
